# 设计思路与信息架构

## 设计目标

本项目的目标不是替代真实 WorkBuddy 客户端，而是建立一个面向初学者的“**可操作产品导览**”。用户能在高保真界面里点击、选择、发送消息和推进任务，并在关键节点获得解释。设计选择以“真实感、可理解性、低遮挡”三者的平衡为中心。[1] [2]

| 目标 | 设计回应 | 验证方式 |
|---|---|---|
| 贴近真实客户端 | 使用桌面应用三栏布局、macOS 风格、灰白底色与品牌绿。 | 主页面和设置页源码、用户提供截图。 |
| 适合初学者 | 对功能区域、设置项和术语建立分层教学机制。 | FeatureDrawer、SettingsModal、GuidePage。 |
| 避免教学打断操作 | 功能说明改为右侧抽屉；设置项说明采用悬浮浮层。 | Tooltip fixed 定位实现与版本历史。 |
| 展示可感知的 AI 过程 | 提供对话流式输出、桌面整理、工作空间选择等情景模拟。 | ChatSimulator、DesktopTaskSimulator、WorkspaceModal。 |
| 鼓励探索 | 使用探索进度条与邀请码彩蛋。 | useProgress、ProgressBar、EasterEgg。 |

## 视觉规则

| 维度 | 规则 | 设计理由 |
|---|---|---|
| 主色 | WorkBuddy 绿 `#00C48C` | 用于选中态、可点击高亮、CTA 和教学强调，建立识别度。 |
| 基础色 | 白色主内容区、浅灰侧边栏、深灰正文 | 接近真实桌面客户端，优先阅读稳定性。 |
| 字体 | `Noto Sans SC`、`PingFang SC`、`Microsoft YaHei`、系统字体；英文与数字可用 Inter | 保证中文说明密度较高时的可读性。 |
| 布局 | 左侧导航 + 中央内容 + 右侧抽屉 | 以应用界面而非居中落地页为结构原型。 |
| 交互高亮 | 绿色虚线边框、问号、轻量动效 | 告诉初学者“这里可以探索”，同时避免永久覆盖界面。 |
| 动效 | 100–250ms 为主，抽屉和教学卡片只使用 transform/opacity | 保持响应轻快，减少干扰。 |

## 用户流程

| 阶段 | 用户动作 | 系统反馈 | 教学目的 |
|---|---|---|---|
| 发现 | 进入主界面，看到任务、模式、快捷入口 | 可点击区域有绿色虚线提示 | 让用户理解界面是可探索的。 |
| 理解 | 点击功能区域 | 右侧抽屉显示说明、步骤与小贴士 | 用简洁解释降低首次使用门槛。 |
| 体验 | 打开对话、桌面整理或工作空间模拟 | 按真实顺序展示输入、执行和结果 | 让抽象能力转化为可感知过程。 |
| 深学 | 打开功能指南和设置 | 长页内容、自动教学卡、术语浮层 | 支持从“知道”走向“会用”。 |
| 激励 | 完成多类探索 | 进度条更新，最终显示邀请码彩蛋 | 鼓励完整浏览而不强制线性教程。 |

## 关键交互与决策

### 功能解释：从遮罩 Modal 到右侧 Drawer

早期功能介绍会遮挡主界面。用户明确提出“不要弹出解释后就遮挡了全屏”，因此调整为右侧滑入抽屉。抽屉保留正在被解释的应用界面，使用户能把“说明”与“位置”关联起来。[2]

### 设置教学：自动卡片 + 细项问号

设置页最需要教学，但持续占据内容区又会打断操作。最终采用两层结构：切换设置子页时自动显示页面级教学卡片；细项的定义和建议通过问号悬浮提示按需查看。Tooltip 使用 `fixed` 定位，以避免父容器 `overflow:hidden` 裁剪浮层。[3]

### 功能指南：资料原文优先

用户多次强调 PDF 与飞书内容“不能删改”。因此功能指南以内容完整性为优先，设计上使用 Awwwards Messenger 式的黑底章节 Hero、长页面叙事与边栏补充，但不以“摘要化”替代原文结构。[2] [4]

## 信息架构边界

本演示站为纯前端模拟，不连接真实 WorkBuddy 账号、模型 API、文件系统或自动化执行引擎。所有任务执行、工作空间和对话结果均是预设的演示状态；模型配置表单仅用于教学和界面还原，不会传输 API Key。[5]
