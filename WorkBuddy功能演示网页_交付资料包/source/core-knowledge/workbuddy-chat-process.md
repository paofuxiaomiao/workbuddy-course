# WorkBuddy 功能演示网页：聊天过程归档

> **归档范围**：本次 WorkBuddy 功能演示网页从需求提出、界面制作、交互迭代、内容补全到导出资料的主要对话过程。  
> **整理方式**：保留用户需求、实施回应、关键修改和交付节点；为了可读性，对重复的状态通知和底层执行细节做了合并。  
> **说明**：本文件仅为本地归档附件，**不会上传或提交到 GitHub**。

## 01. 项目启动：制作 WorkBuddy 教学演示网页

| 角色 | 对话内容 / 行动 |
|---|---|
| 用户 | 提出需求：制作一个“假的 WorkBuddy 网页”，用于介绍 WorkBuddy 功能；提供多张不同功能页的截图，并给出飞书文档链接作为参考。要求面向初学者，交互应与正常网站一致，但点击功能时展示对应介绍。 |
| 助手 | 确认制作方向：将读取飞书文档与官网资料，构建一个可交互的 WorkBuddy 功能演示网页。 |
| 助手 | 建立实施计划：内容调研、界面还原、交互介绍、验收交付。 |
| 助手 | 初始化 `workbuddy-demo` React 前端项目，并创建设计方案文档。 |

### 初始设计决策

设计方案经过三种方向比较后，选定了 **“轻量仿真 + 弹窗介绍”**：以真实 WorkBuddy 的 macOS 风格桌面客户端为视觉基础，使用灰白界面与 WorkBuddy 品牌绿；用户悬停可交互区域时出现绿色虚线与问号，点击后得到新手友好的功能解释。

## 07. 设置页面教学说明的多轮优化

| 角色 | 对话内容 / 行动 |
|---|---|
| 用户 | 反馈：设置里的教学内容缺失，但设置页是最需要教学的地方；提供“记忆”真实设置页截图。 |
| 助手 | 在 10 个设置子页面加入“新手必读”说明，介绍功能用途、新手建议和操作要点。 |
| 用户 | 明确要求：解释不要放在页面里面，要悬浮在外面。 |
| 助手 | 移除嵌入式教学横幅，改为每个设置项旁的问号悬浮说明。 |
| 用户 | 反馈问号打不开。 |
| 助手 | 定位根因：设置弹窗使用 `overflow:hidden`，导致悬浮卡片被裁剪；改为 fixed 定位和动态位置计算。 |
| 用户 | 继续说明：设置里的讲解需要自动跳出来，这里很重要。 |
| 助手 | 加入设置子页面自动弹出的教学卡片，用户切换页面后第一时间看到该页说明，可关闭。 |

### 最终设置教学体验

设置教学形成两层结构：

1. **页面级自动教学卡片**：切换到系统设置、智能体设置、记忆、模型、个性化等任何子页时自动出现，介绍这个页面的核心用途与推荐操作。
2. **设置项级问号解释**：每个具体设置项旁边保留问号，悬停时显示外置浮层；采用 fixed 定位，确保不会被设置窗口裁剪。
